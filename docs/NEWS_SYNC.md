# Новости из Google Таблицы

Таблица — источник публикаций. Backend получает CSV раз в час и хранит
последнюю успешную версию в SQLite. Посетители читают существующий `/api/news`,
без запросов к Google при открытии сайта. Отдельная админка для этой ленты не нужна.

## Таблица

Используем существующий лист:
https://docs.google.com/spreadsheets/d/1Mr5aAkXqf3oxg-hXaZcZk2AKy15kQF_rkkZrFb6rdz4/edit

Обязательные колонки: `title`, `date`, `text`, `source`, `images`, `status`.
`category` и `comments` можно сохранить, добавлять другие колонки не требуется.

- `status`: публикуются только строки со значением `готово` (регистр не важен).
  «Собрано», «уточнить» и другие значения не публикуются. Изменение статуса
  опубликованной строки убирает её из ленты при следующей успешной проверке.
- `date`: исходная дата публикации в формате `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`.
- `source`: прямая ссылка `https://t.me/<канал>/<номер_поста>`.
  Это постоянный ключ: сортировка таблицы и изменение заголовка не создают дубль.
  При замене `source` прежняя публикация удаляется, новая добавляется.
  При желании можно добавить постоянный уникальный `id` — он заменит ключ из `source`.
- `images`: ссылки на общедоступные фото или видео Google Drive через пробел или новую строку;
  для видео сайт показывает только готовое превью Google Drive, без видеоплеера.
  пустая ячейка или `-` означает отсутствие картинок. Для нескольких картинок
  можно дать ссылку на папку (до 12 изображений, порядок по имени файла).
- `comments` остаётся внутренним полем таблицы и не выдаётся посетителям.

Таблица и файлы должны быть доступны для просмотра по ссылке. Права редактирования
оставьте только участникам команды. Backend ничего не записывает в Google.

## Включение

В окружении приложения задайте:

```dotenv
MOSPHYSICS_NEWS_SHEET_ID=1Mr5aAkXqf3oxg-hXaZcZk2AKy15kQF_rkkZrFb6rdz4
MOSPHYSICS_NEWS_SHEET_GID=0
```

При пустом `MOSPHYSICS_NEWS_SHEET_ID` синхронизация отключена. В Docker Compose
переменные берутся из корневого `.env`; файл не коммитится. Изображения сохраняются
в `/data/news-media` в существующем постоянном томе. В обычном запуске — в
`news-media` рядом с БД; путь можно задать `MOSPHYSICS_NEWS_MEDIA`.

Для ссылок на папки нужен `GOOGLE_DRIVE_API_KEY` из Google Cloud проекта
с включённым Google Drive API. Ограничьте ключ этим API; для сервера с постоянным
IP можно также ограничить по IP. Ключ хранится только в окружении, не в таблице.
Без него используйте прямые ссылки на отдельные файлы вместо ссылки на папку.
Никакого ключа для CSV и отдельных общедоступных файлов не требуется.

При старте первая проверка запускается в фоне, затем раз в 3600 секунд.
Время последней попытки хранится в SQLite: перезапуск или несколько workers
не создают лишних загрузок. После ошибки следующая попытка также через час.
Однократная команда использует ту же защиту от частых запросов:

```bash
python -m backend.news_sync
```

## Сохранность

Миграция 3 добавляет `sheet_news` и `news_sync_state`, сохраняя существующие
новости и пользователей. Перед production-обновлением сохраните резервную копию
по существующей процедуре. Старые локальные новости остаются в общей ленте;
синхронизация удаляет только записи своего листа.

Сначала проверяется весь CSV и загружаются изображения, затем одна транзакция
добавляет/обновляет/удаляет публикации. Ошибка сети, HTML вместо CSV, дубли,
неверная дата или недоступная картинка сохраняют предыдущую версию целиком.
Корректная таблица с заголовками и без готовых строк намеренно очищает публикации
этого листа. Удаление колонок — ошибка, не команда очистки.

Скачиваются изображения превью Google Drive JPEG/PNG/WebP: до 10 МБ и 20 млн пикселей.
Используется endpoint thumbnail с шириной до 1600 px; оригиналы видео не скачиваются.
Сайт перекодирует картинки в JPEG до 1600 px, без EXIF и исходных имён файлов.
Ссылки на произвольные серверы и редиректы за пределы Google запрещены.
Удалённые изображения автоматически не очищаются: публикации исчезают сразу,
а файлы остаются для восстановления. Планируйте свободное место отдельно.

В журнале: `News sync succeeded` с числом публикаций или `News sync failed`
с типом ошибки; ключ API и URL загрузки не записываются. Текущее состояние можно
прочитать локально из `news_sync_state` без публичного административного API.

Перед включением на сервере проверить добавление, изменение, смену статуса,
удаление и недоступность Google на отдельной БД. Настройка SMTP и остальные
разделы сайта не входят в эту задачу.

## VPS: настройка от 04.10.2026

Синхронизация включена в контейнере `mosphysics-hermes-rebuild-prod`,
образ `mosphysics:news-sync-20261004-093950`, порт `9090`.
Настройки сохранены в закрытом файле
`/srv/apps/mosphysics-hermes-rebuild/news-sync-20261004-093950.env` (права 600).
Не выводите его содержимое в журнал и не коммитьте.
Рабочие данные: `/srv/apps/mosphysics-hermes-rebuild/production-data`.
Ключ Drive API не задан: используйте отдельные файлы вместо папок.

Проверены резервное копирование SQLite и восстановление в отдельную БД,
миграция 3 на копии, совместимость старого образа с миграцией и health-check.
После проверки материалов и включения превью видео опубликованы 10 новостей.
Проверены `/news`, `/api/news` и доступность всех 14 изображений через HTTP.
04.10 после восстановления Nginx проверен публичный HTTPS: `/api/health`
отвечает `ok`, `/news` — HTTP 200, `/api/news` отдаёт 10 новостей.
Причина недоступности: при загрузке VPS 02.10 Nginx не смог занять
`172.24.0.1:18080`, поскольку адрес Docker-сети ещё отсутствовал.
После появления сети конфигурация проходит `nginx -t`; выполнен `systemctl start nginx`.
В unit nginx нет зависимости от Docker; порядок загрузки не изменён,
риск повторения при следующем перезапуске остаётся.

Для отката приложения остановите текущий контейнер, переименуйте его,
верните имя `mosphysics-hermes-rebuild-prod` сохранённому контейнеру
`mosphysics-before-news-sync-20261004-093950` и запустите его.
Схему БД откатывать для старой сборки не требуется.
Проверенная резервная копия находится в
`production-data/.news-sync-backups/before-20261004-093950.sqlite`.
Не восстанавливайте её поверх рабочей БД без отдельного согласования:
это удалит изменения после копирования.
