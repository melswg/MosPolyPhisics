# Отправитель noreply@mospolyphysics.ru через Resend

Выбран Resend: нужен адрес отправителя служебных писем, входящий ящик не нужен.
04.10.2026 домен подтверждён в Resend, ключ добавлен владельцем в закрытый
файл и подключён к рабочему контейнеру. SMTP-авторизация прошла; Resend принял
одно тестовое письмо на явно указанный владельцем адрес. Владелец подтвердил
получение письма.
Nameservers домена — ns1.reg.ru и ns2.reg.ru. DKIM, DMARC и два CNAME
проверены непосредственно на авторитетном DNS-сервере REG.RU.

## Действия владельца

1. Зарегистрироваться или войти на https://resend.com.
2. В Domains добавить **mospolyphysics.ru**. Включить отправку; входящие письма
   для этой задачи не требуются. Отключить отслеживание открытий/кликов
   для писем восстановления, чтобы не изменялись служебные ссылки.
3. Скопировать выданные Resend записи подтверждения в DNS-зону домена
   в панели REG.RU. Имена, типы и значения брать из своего аккаунта:
   ключ DKIM индивидуальный, готовые значения не угадывать.
   Не менять A-запись сайта, nameservers и записи чужих сервисов.
4. Нажать Verify и дождаться статуса Verified.
5. Создать API-ключ с правом Sending access для этого домена.
   Ключ в Resend используется как пароль SMTP. Не вставлять его в чат,
   GitHub, таблицу или публичные скриншоты.
6. Добавить ключ в закрытый runtime env-файл VPS как SMTP_PASSWORD.
   Для этого удобно редактировать файл через терминал, не вводя ключ
   непосредственно в командную строку или историю команд.

## Конфигурация

Шаблон без секретов — `deploy/smtp.env.example`. Для Resend:

```dotenv
SMTP_FROM=noreply@mospolyphysics.ru
SMTP_HOST=smtp.resend.com
SMTP_PORT=2587
SMTP_USERNAME=resend
SMTP_PASSWORD=<API_KEY_FROM_RESEND>
SMTP_USE_TLS=true
SMTP_USE_SSL=false
```

Значение в угловых скобках — placeholder, не рабочий ключ.
Порт 2587 выбран после проверки с VPS: STARTTLS с Resend успешно установил
TLS 1.3. Порты 587 и 465 при проверке завершились тайм-аутом.
Закрытый файл настроек:
`/srv/apps/mosphysics-hermes-rebuild/news-sync-20261004-173840.env`.
SMTP_PASSWORD задан; его значение не записывается в документацию или Git.
Рабочий контейнер пересоздан с этими настройками, отправка включена.
После изменения env-файла Docker-контейнер нужно пересоздать с ним:
обычный docker restart не перечитывает env-файл. Остальные переменные,
постоянный том, порт и health-check должны сохраняться.
Путь актуального закрытого файла записан в `docs/NEWS_SYNC.md`.
Перед переключением нужны резервная копия и проверка нового контейнера
на отдельном порту по принятому порядку развёртывания.

## Проверка

В контейнере без отправки писем:

```bash
docker exec mosphysics-hermes-rebuild-prod python -m backend.check_smtp
```

После выбора владельцем адреса получателя:

```bash
docker exec mosphysics-hermes-rebuild-prod python -m backend.check_smtp --to YOUR_EMAIL
```

Успешный SMTP-ответ означает принятие письма сервером. Доставку подтверждает
письмо во входящих или папке спама и статус доставки в Resend.
Затем пройти восстановление на сайте с зарегистрированным адресом.
По выбору владельца сохраняем одноразовую ссылку на 30 минут. Новый запрос
возможен через минуту и отменяет предыдущую ссылку. После смены пароля все
сеансы завершаются; вход выполняется обычным способом с новым паролем.
В новых письмах секрет передаётся во фрагменте URL, который браузер не отправляет
в HTTP-запросах. Страница удаляет его из адресной строки после загрузки;
старые ссылки с query-параметром также поддерживаются.
